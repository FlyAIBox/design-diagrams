# Design Resources

Use external resources selectively. They are inputs to judgment, not a checklist and not a substitute for the Project Style DNA.

## Resource roles

| Resource | Use it for | Do not use it for |
| --- | --- | --- |
| [Refero Styles](https://styles.refero.design/) | donor `design.md`, layout rhythm, typography and spacing ideas | copying a whole style unchanged |
| [Dribbble](https://dribbble.com/) | broad visual exploration and composition references | evidence that a design works in real use |
| [Recent Design](https://recent.design/) | current interface and editorial patterns | importing a trend without semantic need |
| [Mobbin](https://mobbin.com/) | real product-flow and screen-pattern references | turning a technical diagram into an app mockup |
| [Cue Design](https://www.cuedesign.space/) | curated paid design references when access is available | assuming assets are licensed for redistribution |
| [React Bits](https://reactbits.dev/) | an explicitly requested Interactive Variant | static SVG or PNG decoration |
| [Hugeicons](https://hugeicons.com/) | a small number of semantic icons with verified licensing | replacing readable labels with icon guessing |
| [Pexels](https://www.pexels.com/) | photography when the diagram genuinely needs real-world imagery | decorative backgrounds or unrelated stock photos |

## Donor-design workflow

1. Start from the subject's semantic brief and Project Style DNA.
2. Select one donor whose information density and reading pattern match the subject.
3. Extract no more than a few decisions: composition, scale contrast, spacing cadence, grouping, and emphasis.
4. Translate those decisions into project tokens and semantic shapes.
5. Remove donor branding, colors, logos, screenshots, unique illustration language, and unnecessary effects.
6. Compare the result against the Style DNA and the diagram's claim. If the donor weakens either, discard the donor decision.

Do not blend several fashionable references indiscriminately. One coherent visual grammar is more useful than a collage of trends.

## Asset and licensing discipline

- Record the URL and access date for externally sourced assets when the project requires provenance.
- Check the current license before redistributing icons, photos, templates, or paid resources.
- Prefer text and native SVG geometry for technical diagrams. External assets should be exceptional and semantically necessary.
- Never package paid or restricted donor files into this skill.
